# Замена диска в Ubuntu: RAID5 + GPT + BIOS/Legacy + GRUB

## 1. Подтверждённая конфигурация

По присланным выводам:

-   Загрузка выполняется в режиме **BIOS/Legacy**, не UEFI.
-   Диски имеют таблицу разделов **GPT**.
-   На каждом диске два раздела:
    -   раздел №1, размер 1 MiB, тип `BIOS boot` (GPT type GUID
        `21686148-6449-6e6f-744e-656564454649`);
    -   раздел №2, примерно 931.5 GiB, тип `Linux RAID`.
-   В RAID5 `/dev/md0` входят `/dev/sda2`, `/dev/sdb2`, `/dev/sdc2`,
    `/dev/sdd2`.
-   `/dev/md0` используется как LVM physical volume (`LVM2_member`).
-   В LVM находятся `vg0/lv-boot` (3 GiB, ext4, смонтирован в `/boot`) и
    `vg0/lv-root` (корневая файловая система `/`).
-   Отдельного EFI System Partition и `/boot/efi` в показанном выводе
    нет.
-   Неисправный физический диск ранее определён по SMART как `/dev/sdd`,
    serial `WDEAD05W`. Перед операцией это нужно подтвердить снова:
    имена `/dev/sdX` могут измениться.

Таким образом, раздел №1 --- **не копия файлового раздела `/boot`**. Это
BIOS Boot Partition: небольшая служебная область, куда GRUB для BIOS на
GPT помещает свой загрузочный образ `core.img`. Сам `/boot` находится
внутри LVM на RAID-массиве.

## 2. Важные меры безопасности

1.  До работ сделайте и проверьте резервную копию важных данных.
2.  Подготовьте новый диск, который имеет не меньше секторов, чем
    старый. Сравнивайте число секторов, а не округлённую надпись «1 TB».
3.  Не отключайте диск физически, пока не проверены serial и состояние
    массива.
4.  Не выполняйте команды записи, пока не установлены точные имена
    старого и нового дисков.
5.  Во время восстановления RAID5 массив будет работать без
    отказоустойчивости. Второй отказ может привести к потере данных.
6.  Не запускайте `badblocks` и длительные тесты на старом диске: SMART
    уже показал media errors.

## 3. Предварительные проверки

### 3.1. Состояние массива

``` bash
cat /proc/mdstat
sudo mdadm --detail /dev/md0
```

Перед началом ожидается четыре активных участника, `[UUUU]`, `clean`,
`Failed Devices : 0`. Если массив уже деградировал или есть ошибки
второго диска, остановитесь и сначала оцените риски.

### 3.2. Идентификация дисков

``` bash
lsblk -o NAME,SIZE,MODEL,SERIAL,TYPE,FSTYPE,PARTTYPE,PARTUUID,MOUNTPOINTS
ls -l /dev/disk/by-id/
sudo smartctl -i /dev/sdd
```

Убедитесь, что старый диск --- действительно serial `WDEAD05W`. Запишите
serial нового диска после подключения. Не полагайтесь только на
`/dev/sdd` или `/dev/sde`.

Для дальнейших примеров: - `OLD_DISK` --- физический диск с serial
`WDEAD05W` (ранее `/dev/sdd`); - `NEW_DISK` --- новый физический диск,
определённый по serial; - `NEW_DISK2` --- раздел №2 нового диска.

Это поясняющие обозначения, не вводите их буквально. Подставляйте
фактические устройства, например `/dev/sde` и `/dev/sde2`, только после
проверки serial.

### 3.3. Проверка разметки исправного диска

Показанный `/dev/sda` имеет GPT и следующую схему:

``` text
/dev/sda1   2048       4095       2048 sectors    1 MiB   BIOS boot
/dev/sda2   4096 1953521663 1953517568 sectors  931.5 GiB Linux RAID
```

Проверьте, что другие исправные диски имеют те же границы разделов:

``` bash
sudo fdisk -l /dev/sda
sudo fdisk -l /dev/sdb
sudo fdisk -l /dev/sdc
sudo sgdisk -p /dev/sda
```

Если разметка отличается, не копируйте её без дополнительного анализа.

### 3.4. Проверка GRUB и LVM

``` bash
findmnt /boot
sudo pvs
sudo vgs
sudo lvs -a -o +devices
sudo grub-probe /
sudo grub-probe /boot
```

`/boot` в предоставленном `lsblk` находится на
`/dev/mapper/vg0-lv--boot`, то есть внутри LVM на `/dev/md0`. Это важно:
копировать отдельную файловую систему `/boot` на новый физический диск
не требуется.

## 4. Подключение и подготовка нового диска

Подключите новый диск. До проверки не запускайте форматирование,
`wipefs`, `mkfs` или копирование таблицы разделов.

Определите его serial и размер:

``` bash
lsblk -o NAME,SIZE,MODEL,SERIAL,TYPE
sudo smartctl -i /dev/НОВЫЙ_ДИСК
sudo blockdev --getsz /dev/НОВЫЙ_ДИСК
sudo blockdev --getsz /dev/sda
```

Замените `НОВЫЙ_ДИСК` на фактическое имя, например `/dev/sde`.

Новый диск должен иметь не меньше секторов, чем исходный. Также раздел
№2 на нём должен иметь не меньше секторов, чем `/dev/sda2`.

### 4.1. Копирование GPT-разметки

**Следующая операция перезаписывает таблицу разделов нового диска.
Убедитесь, что назначение --- именно новый диск и на нём нет нужных
данных.**

Пример, если новый диск действительно `/dev/sde`, а исправный источник
--- `/dev/sda`:

``` bash
sudo sgdisk --replicate=/dev/sde /dev/sda
sudo sgdisk -G /dev/sde
sudo partprobe /dev/sde
sudo udevadm settle
```

-   `--replicate` копирует таблицу разделов с исправного диска.
-   `-G` генерирует новые GUID диска и разделов, чтобы не дублировать
    идентификаторы.
-   Таблица должна содержать раздел №1 типа BIOS boot и раздел №2 типа
    Linux RAID.

Проверьте:

``` bash
sudo fdisk -l /dev/sde
sudo sgdisk -p /dev/sde
lsblk -o NAME,SIZE,TYPE,PARTTYPE,PARTUUID /dev/sde
sudo blockdev --getsz /dev/sde2
sudo blockdev --getsz /dev/sda2
```

Не продолжайте, если раздел №1 не имеет типа BIOS boot, раздел №2 меньше
исходного, границы не совпадают или команда выдала ошибку.

**Не копируйте первые 512 байт диска командой `dd`:** это может
скопировать MBR/GPT protective data и идентификаторы, которые не следует
дублировать.

## 5. Вывод неисправного участника из RAID5

Перед операцией ещё раз проверьте:

``` bash
cat /proc/mdstat
sudo mdadm --detail /dev/md0
```

Подтвердите, что `/dev/sdd2` --- участник с неисправного диска serial
`WDEAD05W`, и массив всё ещё имеет четыре активных участника.

Пометьте участника отказавшим:

``` bash
sudo mdadm --manage /dev/md0 --fail /dev/sdd2
```

Проверьте результат:

``` bash
cat /proc/mdstat
sudo mdadm --detail /dev/md0
```

Затем удалите его из массива:

``` bash
sudo mdadm --manage /dev/md0 --remove /dev/sdd2
```

Снова проверьте:

``` bash
cat /proc/mdstat
sudo mdadm --detail /dev/md0
```

Теперь массив должен продолжать работу на трёх оставшихся участниках.
Если команда выдаёт ошибку или состояние отличается от ожидаемого ---
остановитесь и сохраните вывод для анализа.

## 6. Физическая замена

### Если поддерживается hot-swap

После успешных `--fail` и `--remove` можно извлечь только диск с
подтверждённым serial `WDEAD05W`, следуя инструкции производителя
сервера/корзины.

### Если hot-swap не поддерживается

1.  Убедитесь, что массив после удаления участника работает на трёх
    дисках.
2.  Выключите сервер:

``` bash
sudo poweroff
```

3.  Отключите питание.
4.  Извлеките диск serial `WDEAD05W` и установите новый.
5.  Включите сервер.
6.  Снова определите новый диск по serial:

``` bash
lsblk -o NAME,SIZE,MODEL,SERIAL,TYPE
ls -l /dev/disk/by-id/
```

После перезагрузки имя нового диска может измениться. Не используйте
старое имя без повторной проверки.

## 7. Добавление нового раздела в RAID

Убедитесь, что новый диск и его раздел №2 идентифицированы правильно,
размер раздела подходит, а в массиве остались три правильных участника.

Пример, если новый раздел действительно `/dev/sde2`:

``` bash
sudo mdadm --manage /dev/md0 --add /dev/sde2
```

Не запускайте `mdadm --create`, `mkfs` или `--zero-superblock` для
обычной замены участника существующего массива.

Проверьте:

``` bash
cat /proc/mdstat
sudo mdadm --detail /dev/md0
```

Если новый диск добавлен как spare, но recovery не начинается, не
запускайте наугад дополнительные команды. Сохраните выводы для
диагностики.

## 8. Восстановление RAID

Наблюдайте за восстановлением:

``` bash
watch -n 2 cat /proc/mdstat
```

Выйти из `watch` можно `Ctrl+C`; это не останавливает восстановление.

Во время восстановления: - не выключайте сервер без необходимости; - не
отключайте диски; - не запускайте `badblocks`; - по возможности
ограничьте тяжёлую дисковую нагрузку; - проверяйте сообщения ядра:

``` bash
sudo dmesg -T | grep -Ei 'ata|I/O error|UNC|failed|reset|offline|md'
```

После завершения:

``` bash
cat /proc/mdstat
sudo mdadm --detail /dev/md0
sudo smartctl -a /dev/НОВЫЙ_ДИСК
```

Ожидается `[4/4] [UUUU]`, `State : clean`, `Active Devices : 4`,
`Working Devices : 4`, `Failed Devices : 0`.

## 9. Установка GRUB на новый диск (BIOS + GPT)

В этой конфигурации раздел №1 --- BIOS Boot Partition размером 1 MiB. Он
не монтируется и не содержит обычные файлы `/boot`. Сам `/boot`
расположен на LVM logical volume внутри RAID5.

После того как новый диск добавлен в RAID и массив полностью
восстановлен, установите GRUB в загрузочную область **самого нового
физического диска**, не в раздел №1 и не в раздел №2.

Сначала проверьте, что пакет BIOS-версии GRUB установлен:

``` bash
dpkg -l | grep -E 'grub-pc|grub2-common'
```

Проверьте, что GRUB видит BIOS Boot Partition и `/boot`:

``` bash
sudo grub-probe --target=partmap /boot
sudo grub-probe --target=abstraction /boot
sudo grub-probe /boot
```

Затем, подставив реальное имя нового физического диска, например
`/dev/sde`:

``` bash
sudo grub-install --target=i386-pc --recheck /dev/sde
```

Обратите внимание: - указывается `/dev/sde`, а не `/dev/sde1` и не
`/dev/sde2`; - команда предназначена для BIOS/Legacy и GPT с BIOS Boot
Partition; - выполняйте её только после проверки, что `/dev/sde` ---
новый диск; - если `grub-install` сообщает об ошибке embedding,
отсутствующем BIOS Boot Partition или неизвестной файловой системе, не
применяйте `--force`; сохраните полный текст ошибки.

После успешной установки обновите меню GRUB:

``` bash
sudo update-grub
```

Для установки GRUB на остальные исправные диски (если это требуется для
резервной загрузки) используйте отдельное окно обслуживания и точно так
же проверяйте каждое устройство. Не нужно переустанавливать GRUB на
старом неисправном диске перед его извлечением.

### Проверка возможности загрузки с нового диска

Успешный `grub-install` подтверждает установку загрузчика, но не
гарантирует, что BIOS сервера настроен загружаться с этого диска. После
завершения RAID recovery: 1. проверьте порядок загрузки дисков в BIOS
Setup; 2. запланируйте контролируемую перезагрузку; 3. убедитесь, что
система загрузилась, `/boot` и `/` доступны, а RAID собрался корректно.

Не отключайте произвольно другие диски на работающем сервере для
проверки.

## 10. Конфигурация mdadm и initramfs

Проверьте конфигурацию:

``` bash
cat /etc/mdadm/mdadm.conf
sudo mdadm --detail --scan
```

Убедитесь, что `ARRAY` соответствует существующему массиву и его UUID.
Не заменяйте весь `/etc/mdadm/mdadm.conf` выводом одной команды:
сохраните остальные параметры и записи.

После проверки конфигурации обновите initramfs:

``` bash
sudo update-initramfs -u -k all
```

Затем:

``` bash
cat /proc/mdstat
sudo mdadm --detail /dev/md0
```

## 11. Если что-то пошло не так

Остановитесь и не продолжайте, если: - серийный номер не совпадает; -
массив до начала работ уже имеет менее трёх рабочих участников; - на
другом участнике появляются ошибки SMART/I/O; - новый диск меньше
старого; - раздел №2 нового диска меньше `/dev/sda2`; - GPT-разметка
скопирована некорректно; - `mdadm --add` завершился ошибкой или recovery
не начинается; - GRUB сообщает об ошибке embedding или BIOS Boot
Partition; - во время recovery появляются новые I/O/UNC/SATA reset.

Сохраните вывод:

``` bash
cat /proc/mdstat
sudo mdadm --detail /dev/md0
sudo dmesg -T | tail -200
lsblk -o NAME,SIZE,MODEL,SERIAL,TYPE,FSTYPE,PARTTYPE,MOUNTPOINTS
```

Не пытайтесь исправлять проблему командами `mdadm --create`, `--force`,
`--zero-superblock`, `wipefs`, `mkfs` или удалением разделов без
отдельного плана.

## 13. Команды, которые пока нельзя запускать без уточнения имён

Ниже только схема, не готовый блок для копирования. Замените устройства
после проверки серийных номеров и размеров:

``` bash
# Копирование GPT с исправного диска на новый диск:
sudo sgdisk --replicate=/dev/NEW_DISK /dev/sda
sudo sgdisk -G /dev/NEW_DISK
sudo partprobe /dev/NEW_DISK

# Исключение старого участника:
sudo mdadm --manage /dev/md0 --fail /dev/OLD_DISK2
sudo mdadm --manage /dev/md0 --remove /dev/OLD_DISK2

# Добавление нового раздела:
sudo mdadm --manage /dev/md0 --add /dev/NEW_DISK2

# После полного восстановления — GRUB на весь новый диск:
sudo grub-install --target=i386-pc --recheck /dev/NEW_DISK
sudo update-grub
```

**Итог:** по предоставленным данным загрузочная схема теперь понятна:
BIOS/Legacy + GPT + BIOS Boot Partition 1 MiB + `/boot` на LVM внутри
RAID5. Это позволяет дать правильное направление для восстановления
GRUB: устанавливать его на новый физический диск, а не копировать туда
отдельную файловую систему `/boot`.
